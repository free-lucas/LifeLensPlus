# 悬浮窗特效与右键菜单（Floating Launcher Effects）

Phase 13.1。Phase 13 的悬浮入口只会「亮着」：录制与否看不出来，截了图、分析完了也没有任何反馈，
退出只能回主界面点按钮。这一阶段给圆标加上**真实事件驱动**的反馈与一个右键菜单，
不碰截图 / AI / SQLite / LanceDB 任何一条业务链路，也不引入任何新依赖（特效纯 CSS + 内联 SVG）。

设计底线：**不造假状态、不轮询**。每一个视觉变化都挂在一次真实事件上。

## 1. 四类视觉与它们的触发源

| 视觉 | 类型 | 触发事件 | 时长 | 实现 |
| --- | --- | --- | --- | --- |
| 录制中：轨道环旋转 + 瞳孔青色呼吸 | 持续态 | `status.running = true` | 一直 | `body.state-running` |
| 已暂停：环停转、瞳孔变暗偏灰、整体亮度降一档、呼吸光晕也停 | 持续态 | `status.running = false` | 一直 | `body.state-paused` |
| 快门闪光 + 小镜得意 | 瞬时 | `record`（刚截完一张图） | 0.4s | `body.effect-shutter` |
| 光圈绿闪 + 小镜开心 | 瞬时 | `analysis`（AI 结果写回） | 0.6s | `body.effect-success` |
| 红闪 + 小镜疑惑 | 瞬时 | `error` | 0.5s | `body.effect-error` |

持续态靠切换 body class 表达（不是闪烁）；瞬时态在动画结束时自动摘掉 class。
四类事件都来自录制器 / AI 链路，没有一处是「按定时器假装」。

## 2. 事件通道：launcher 为什么不能收 `lifelens:event`

`lifelens:event` 上是完整的业务事件：`record` 带图片路径、`analysis` 带 `screenshotId` 与回填字段、
`error` 带错误文本。收件人却是一个 56x56 的圆标，它只需要知道「要不要闪一下」。
所以给悬浮入口单开一条**裁剪后的通道**：

```text
mainWindow    ← lifelens:event           完整事件（本阶段一个字都没改）
launcherWindow ← lifelens:launcher-event 只有 type（+ status 的 running）
```

转换规则（`src/main/launcher/launcherEvents.js`，纯函数，零 Electron 依赖）：

| 原始事件 | 发给 launcher 的载荷 |
| --- | --- |
| `{ type: 'status', status: { running, …一大堆 } }` | `{ type: 'status', running }` |
| `{ type: 'record', record: { path, project, … } }` | `{ type: 'record' }` |
| `{ type: 'analysis', screenshotId, patch }` | `{ type: 'analysis' }` |
| `{ type: 'error', message }` | `{ type: 'error' }` |
| `ai`（队列快照）等其它类型 | `null` → 不发 |

`running` 只认 `=== true`：字段缺失、`'true'`、`1` 一律按「没在录制」，
宁可显示成暂停，也不要在没截图的时候显出「正在记录」。

### 分流点

分流放在 `main.js` 的 `broadcast()` 里 —— 全应用只有这一个事件出口
（Recorder、TimeBlockSummarizer、DiaryGenerator、AI 队列的 `change` 都走它），
在这里分流是改动最小的做法：

```js
function broadcast(payload) {
  // 主窗口：完整事件（行为不变）
  if (mainWindow && !mainWindow.isDestroyed()) { …send('lifelens:event', payload)… }
  // 悬浮入口：裁剪后的事件。主窗口被关掉（隐藏 / 销毁）时它仍然要收到。
  broadcastLauncher(payload);
}

function broadcastLauncher(payload) {
  const event = launcherEventOf(payload);
  if (!event) return;                                     // 与特效无关的事件直接跳过
  if (!launcherWindow || launcherWindow.isDestroyed()) return;
  launcherWindow.webContents.send(LAUNCHER_EVENT_CHANNEL, event);
}
```

注意 `broadcast()` 的结构：主窗口的发送不再「不满足就 return」，否则主窗口关掉后
悬浮入口就再也收不到特效了。

### 首帧补一次当前状态

`recorder` 在启动时会发一次 `status`，但那一刻 launcher 还没创建。
所以在 `createLauncher()` 里补一次，否则应用以 `autoStart=false` 启动时，
圆标会一直显示成「录制中」——那正是本阶段要消灭的假状态：

```js
launcherWindow.webContents.once('did-finish-load', () => {
  broadcastLauncher({ type: 'status', status: recorder?.status ?? { running: false } });
});
```

## 3. 渲染层：事件只做一件事 —— 切 class

`src/renderer/launcher.js` 里没有一行动画代码，它把事件翻译成 body 上的 class，
视觉全部交给 CSS。两个映射是纯函数（`node --test` 直接测）：

```js
effectClassOf({ type: 'record' })   // 'effect-shutter'
effectClassOf({ type: 'analysis' }) // 'effect-success'
effectClassOf({ type: 'error' })    // 'effect-error'
effectClassOf({ type: 'status' })   // null（status 是持续态，不是特效）
effectClassOf({ type: 'ai' })       // null

stateClassOf(true)   // 'state-running'
stateClassOf(false)  // 'state-paused'
```

细节：

- **持续态**先摘掉两个再挂上对应的一个，任何时候都不会同时存在两个状态；
- **瞬时态**用「先 remove、强制 reflow、再 add」重播：同类事件在动画没播完时又来了，
  动画从头播，而不是被忽略、也不会堆 class；
- **回收**靠 `animationend`：动画名 → class 的映射表（`EFFECT_OF_ANIMATION`）
  只认主光圈那条动画，两个特效叠加时先结束的那个只回收自己；
- **叠加**允许：快门闪光与瞳孔呼吸互不影响，因为它们在元素内部是不同的层。

## 4. CSS 结构（`src/renderer/launcher.css`）

三个特效的光圈都画在 `.ball::after` 上 —— 这一层原本是空的，正好不干扰已有的
`.ball::before`（缓慢扫过的微光）。瞳孔闪烁画在 `.core`，内部高光画在 `.glyph`。

| class | keyframes | 挂在哪 |
| --- | --- | --- |
| `.effect-shutter` | `shutter-ring`（白→青，scale 0.55 → 1.5）+ `shutter-flash`（brightness 1 → 1.7） | `::after` / `.glyph` |
| `.effect-success` | `success-ring`（scale 0.7 → 1.6）+ `success-core`（青 → 绿）+ `success-check`（对勾显隐） | `::after` / `.core` / `.check` |
| `.effect-error` | `error-ring`（红边闪）+ `error-core`（瞳孔红闪） | `::after` / `.core` |

对勾是内联进 `launcher.html` 的 SVG `path`（`.check`，默认 `opacity: 0`），
没有图片、没有外部字体、没有新依赖。

### prefers-reduced-motion

系统开启「减少动态效果」时，光圈不再做位移 / 缩放扩散，只闪颜色：

```css
body.effect-shutter .ball::after { animation-name: shutter-ring-flash; }
body.effect-success .ball::after { animation-name: success-ring-flash; }
```

**特效动画本身不能删**（不能写 `animation: none`）：class 是动画结束后在 `animationend`
里回收的，动画被删掉，class 就会永远留在元素上。瞳孔变色、图标高光、对勾显隐本来就没有位移，
保持原样。

## 5. 小镜（Phase 13.2 三态，Phase 13.3 加待机，Phase 13.4 变默认脸）

**三个瞬时态**现在由小镜（镜头宝宝）上场演，不再只是光圈变色：

| 瞬时态 | 触发事件 | 小镜 | 时长 |
| --- | --- | --- | --- |
| `body.effect-shutter` | `record` | `mascot-smug`：得意（wink + 挑嘴角） | 0.4s |
| `body.effect-success` | `analysis` | `mascot-happy`：开心（月牙眼 + 张嘴笑 + 对勾徽章） | 0.6s |
| `body.effect-error` | `error` | `mascot-thinking`：思考（扫视 + 高低眉 + 思考气泡） | 0.5s |

**待机小镜是悬浮球的默认脸**（Phase 13.3 引入，Phase 13.4 改成默认脸）：
录制中与暂停时都在台上替下那颗光圈圆标，只有三个瞬时态时才让位。
它与上面三只最大的区别是生命周期归谁管 —— 瞬时态由 class 驱动、演完在 `animationend` 里回收；
默认脸由 `body.state-*` 驱动、两个状态都挂着，所以出场动画用的是停在终态的 `mascot-in`，
而不是演完会自己淡出的 `mascot-pop`（详见 [34-小镜待机态](34-小镜待机态.md) 第 5 节）。
它的 SMIL 时间轴跟着录制状态走：录制中放开（在演），暂停冻回第 0 帧（全静止）；
「在不在录」另外还有亮度与外围扫光两个信号，见那一节。

素材在 `src/renderer/assets/mascot-*.svg`（四只，出自 Figma 生成式插件，
几何与色板见 [32-小镜表情动画](32-小镜表情动画.md)），按原样内联在 `launcher.html` 里，
各包一层 `<span class="mascot mascot-<state>">`。

**为什么内联而不是 `<img>`**：CSP 只有 `default-src 'none'`、没有 `img-src`，`<img>` 会被拦掉；
而且 `<img>` 里的 SMIL 自己在循环、没法拨回第一帧，演不出「每次事件都从头演一遍」。

### 时间轴归谁管

小镜的动画是 SMIL，**没有 `animationend`**。所以 Phase 13.1 的回收机制原封不动 ——
生命周期仍然由光圈那条 CSS 动画决定，JS 只在两头搭一把手：

```text
playEffect(name)  -> 挂 class + playMascot()     setCurrentTime(0) + unpauseAnimations()
animationend      -> 摘 class + freezeMascot()   pauseAnimations() + setCurrentTime(0)
```

由此得到四条约束：

- 每只小镜的出场动画时长**必须等于**对应光圈的时长（`mascot-pop` 靠 `animation-duration` 跟），
  否则会出现「光圈还在扩、小镜已经没了」；
- `.mascot` 默认 `opacity: 0` + `visibility: hidden`，页面加载时三只全部
  `pauseAnimations()` + `setCurrentTime(0)` —— 一个 56x56 的常驻窗口里，
  藏着的三只 SVG 不该自己空转；
- `.effect-*` 期间原来的光圈图标 `.glyph` 让位（两者叠在一起会互相打架），
  对勾、瞳孔变色这些细节小镜自己画好了；
- `prefers-reduced-motion` 下**不放时间轴**：小镜停在自己第一帧，只由 `mascot-fade`
  淡入淡出，class 照旧在 `animationend` 里回收。

事件通道与载荷一个字节都没改；`EFFECT_MASCOTS` 是渲染层内部的第三张映射表
（键就是 `EFFECT_CLASSES` 的值，见第 3 节）。

## 6. 右键极简菜单

原生 Electron `Menu`，三项，没有二级菜单、没有自定义 DOM：

```text
打开主界面          ← showOrFocusMainWindow()，与左键同一件事
暂停录制 / 恢复录制  ← 文案由「此刻」的 recorder.running 决定，点下去走 recorder.toggle()
———————————
退出应用            ← app.quit()，走原来的 before-quit 优雅收尾
```

- Renderer 只发一个信号：`contextmenu` → `lifelens:launcher-context-menu`；
- 模板由纯函数 `launcherMenuTemplate({ running, openMain, toggleRecording, quitApp })` 生成，
  所以文案与动作编排可以在纯 Node 里断言，不必真弹一个原生菜单；
- `Menu` 由 main.js 注入（测试传假对象），`menu.popup({ window: launcherWindow })`；
- 窗口已销毁或拿不到 Menu 时返回 `false`，不抛错。

## 8. 明确不做

- 不在 launcher 里展示截图内容 / 分析文本（违反最小暴露）；
- 不做通知中心 / toast / 快捷操作面板 / Widget；
- 不做复杂右键菜单（二级菜单、设置项、快捷记录）；
- 不轮询（特效只由事件驱动）；
- 不引入新依赖（特效纯 CSS + 内联 SVG）；
- ~~不给持续态（录制中 / 已暂停）加表情~~（Phase 13.3 已撤销）：
  待机小镜在两个状态下都是默认脸，见 [34-小镜待机态](34-小镜待机态.md)；
- 不改截图 / AI / SQLite / LanceDB 业务链路；
- 不破坏 Phase 13 的拖动 / 点击 / 隐藏 / 退出逻辑。
