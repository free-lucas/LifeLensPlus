# 悬浮入口（Floating Launcher）

Phase 13。应用不再要求主界面一直开着：桌面上常驻一个 56x56 的悬浮圆标，
点它打开 / 聚焦主界面，关掉主界面它还在。这是一次 **UI / Window Shell 改造**，
不碰截图、AI 队列、embedding、搜索与问答任何一条业务链路。

> Phase 13.1 给这个圆标加了特效与右键菜单（第四个 IPC 通道）：
> 见 [30-悬浮窗特效](30-悬浮窗特效.md)。

## 1. 两个窗口的关系

```text
app.whenReady()
  ├── createWindow()      主窗口（1040x880，index.html，现有行为不变）
  └── createLauncher()    悬浮入口（56x56，launcher.html）  ← 启动末尾创建

关闭主窗口（点 X / Alt+F4）
  └── close 事件 preventDefault + hide()  →  应用继续跑，后台链路不受影响

显式退出（主界面「退出」按钮）
  └── lifelens:quit → app.quit() → before-quit 优雅收尾 → 两个窗口一起销毁
```

| | 主窗口 | 悬浮入口 |
| --- | --- | --- |
| 创建时机 | `whenReady` 里（原有） | `whenReady` 末尾（新增） |
| 关闭按钮 | 隐藏（`close` + `preventDefault`） | 隐藏（同一个规则） |
| 退出时 | `quitting` 置位 → 放行销毁 | 同上 |
| 谁持有它 | `main.js` 的 `mainWindow` | `main.js` 的 `launcherWindow` |

启动行为**没有变**：仍然是主窗口 + 悬浮球同时出现，不会变成「只显示悬浮球」。

## 2. 文件与职责

```text
src/main/launcher/launcherWindow.js     窗口创建、三条 IPC 通道、showOrFocusMainWindow
src/main/launcher/launcherPosition.js   越界校正（纯函数）+ 位置存取（注入 fs）
src/renderer/launcher.html              悬浮图标页面（不加载现有 renderer 脚本）
src/renderer/launcher.css               悬浮球样式（独立成文件，让 CSP 保持 style-src 'self'）
src/renderer/launcher.js                拖动 / 点击手势（纯函数 + createLauncherView）
src/launcherPreload.js                  悬浮入口专用的最小 preload
```

**为什么 launcher 不复用 `src/preload.js`**：那个 preload 暴露了全部业务 API
（记录、时间线、日记、看板、搜索、问答…），而 56x56 的圆标只需要三个窗口操作。
悬浮入口有自己的 preload，暴露面就是三个方法。

## 3. 主窗口生命周期

```js
// main.js
function createWindow() {
  mainWindow = new BrowserWindow({ ... });        // 尺寸 / preload / contextIsolation 都不变
  mainWindow.loadFile(...);
  mainWindow.on('close', (event) => {
    if (quitting) return;      // 显式退出：放行，让 before-quit 的收尾流程走完
    event.preventDefault();
    mainWindow.hide();         // 平时：只隐藏，不销毁、不退出
  });
  mainWindow.on('closed', () => { mainWindow = null; });
}
```

`quitting` 仍然是 `before-quit` 里那个标志，没有新增第二个状态：
两个窗口的 `close` 拦截都读它，所以「退出时不拦截」只有一个判断依据。

### showOrFocusMainWindow

```text
showOrFocusMainWindow({ getWindow, createWindow })
  窗口不存在 / 已销毁 -> createWindow()                  => 'created'
  隐藏 / 最小化       -> restore()（若最小化）+ show()    => 'shown'
  已经可见            -> 只 focus()                      => 'focused'
```

- 写成注入窗口对象的形态，三个分支都能用假窗口单测；
- 三处共用：**launcher 点击**、**`second-instance`**、**macOS `activate`**；
- `activate` 原来是 `getAllWindows().length === 0` 才重建 —— launcher 常驻后这个条件永远为假，
  所以改成调用本地包装 `showMainWindow()`；
- `second-instance` 原来只 `focus()`，主窗口隐藏时唤不出来，同样改成 `showMainWindow()`。

## 4. 退出路径

悬浮入口常驻之后 `window-all-closed` 基本不会再触发，
**应用会失去唯一退出路径**，所以主界面头部新增了一个「退出」按钮：

```text
主界面「退出」按钮
  -> window.lifelens.quit()
  -> ipcMain.handle('lifelens:quit')  →  app.quit()
  -> before-quit（原有流程原样执行：recorder 收尾 → summarizer / diary / embedding 停止
     → aiWorker / aiQueue 收尾 → embedding.flush → vectorStore.close → closeDatabase）
  -> app.quit()（quitting 已置位，两个窗口放行销毁）
```

这是本阶段唯一新增的主窗口 UI。`window-all-closed` 保持原样
（launcher 常驻后正常情况不再触发；退出流程中触发时 `app.quit()` 幂等无害）。

## 5. 拖动与点击

没有用 `-webkit-app-region: drag`：它在 Windows 上会把 drag 区域的 click 一起吞掉，
「拖动 vs 点击」就没法自己判断。改成手动 IPC 拖动 + 阈值判定：

```text
mousedown  -> 记下起点与按下时的窗口位置
mousemove  -> 累计位移 ≤ 4px：什么都不做（还可能是点击）
              累计位移 > 4px：进入拖动，之后每帧把「按下时窗口位置 + 累计位移」发给 Main
mouseup    -> 没进入拖动 = click   -> 打开 / 聚焦主窗口
              进入了拖动 = 拖动结束 -> 保存位置（不打开主窗口）
```

- 阈值判定是纯函数 `gestureOf({ dx, dy }, threshold)`（`Math.hypot` 直线距离，
  正好等于阈值算点击），单测覆盖边界、斜向、坏输入；
- 位置按「按下时的窗口位置 + 累计位移」算，**不读 `window.screenX` 的实时值**：
  快速拖动时不会因为窗口位置刷新时机丢掉位移；
- 三个监听挂在 `document` 上，整个 56x56 窗口都是热区；
- 没有节流 / 惯性 / 吸附，mousemove 直接发 IPC（第一版刻意不做）。

## 6. 位置持久化与越界校正

```text
<userData>/launcher-position.json   { "x": 400, "y": 360 }
```

写 `userData`（LanceDB 的 `userData/lancedb` 已有先例），**不写 `outputDir`**（那是用户图片目录），
**不写 SQLite**。保存时机只有一处：拖动结束（`lifelens:launcher-end`）。
读取失败（文件缺失 / JSON 损坏 / 字段不合法）一律静默回退默认位置（主屏工作区右下角）。

越界校正是纯函数 `clampToWorkArea(position, size, workAreas)`：

```text
输入：保存的 { x, y }、窗口尺寸、所有显示器的 workArea
输出：保证 56x56 完整落在某块可见 workArea 内的位置

选屏：与窗口矩形重叠面积最大的那块；完全不重叠时选中心点最近的那块
      （保存位置所在显示器被拔掉 -> 不会跑到够不着的地方）
夹取：x ∈ [workArea.x, workArea.x + width - 56]，y 同理
      工作区比窗口还小（分辨率变小 / 极端缩放）时贴左上角，保证左上角可见
```

启动时 `clampToWorkArea(saved ?? 默认右下角, ...)`，拖动中每次 `setPosition` 之前也 clamp，
所以窗口任何时候都不会被拖出可见区域（Renderer 传来的坐标一律不信任）。

## 7. IPC

命名沿用 `lifelens:*`，一共三条新通道：

| 通道 | 方向 | Main 侧做什么 |
| --- | --- | --- |
| `lifelens:launcher-open` | `invoke` | `showOrFocusMainWindow()` |
| `lifelens:launcher-move` | `send` | `clampToWorkArea` 后 `setPosition`（高频，无返回值） |
| `lifelens:launcher-end` | `invoke` | 读窗口当前位置并写盘 |

主窗口一侧只有一条 `lifelens:quit`（`app.quit()`）。Renderer 不直接操作 BrowserWindow。

## 8. 明确不做的事

- 快捷记录 / 快速提问 / AI Agent / Widget / 快捷操作面板；
- 右键菜单（包括悬浮球上的退出菜单 —— 退出只走主界面按钮）；
- 托盘图标（悬浮入口本身就是常驻入口，不引入 Tray）；
- 复杂动画、通知中心、多悬浮球。

## 10. 已知取舍

- **跨屏拖动会「跳」一下**：规则是「窗口必须完整落在某块 workArea 内」，
  所以拖过两屏交界时圆标会从一块屏的边缘跳到另一块屏的边缘（最多 56px）。
  这是按需求「完整落在可见 workArea 内」实现的直接结果；
- **聚焦悬浮球按 `Alt+F4` 只是隐藏**，没有托盘 / 菜单能把它叫回来
  （按需求「非退出状态 -> preventDefault + hide」实现）。恢复方式：重新启动应用
  （单实例锁会把主窗口唤起来）；
- **透明窗口没有退化**：本机实测（Windows，2560x1080）透明度正常，圆角外是真透明，
  没有黑底方块，所以没有启用「不透明圆形纯色背景」的兜底样式；
- 拖动没有做节流，极端快速拖动会多打几个 IPC（第一版刻意不做）。
