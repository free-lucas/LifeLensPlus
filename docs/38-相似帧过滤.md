# 相似帧过滤

## 1. 这个功能做什么

每 20 秒截一帧，如果这一帧和**上一张已保存的截图**几乎一样，就直接丢弃：
不写 PNG、不写 `activities` 记录、不入 AI 队列，只把 `Recorder.status.skipped` 加一。
挂机、静止桌面、长时间停在同一个页面时，就不会继续堆重复记录。

两个容易忽略的细节：

- 基准是「上一张**已保存**的截图」，不是「上一帧」。被跳过的一帧不更新基准，
  所以静止画面下基准会一直停在最后一次真实变化的那张。
- `skipped` 只是进程内的计数，重启从 0 开始，不落库。

## 2. 修复的问题：功能在，但从不生效

修复前（`SIMILAR_FRAME_DISTANCE = 5`，从 2026-09-13 初始提交起就是这个值）用的是
**dHash**：把截图缩成 9x8 灰度图，比较每行左右相邻两格谁更亮，得到 64 位指纹，
再看汉明距离是否 ≤ 5。

在真实数据上（3440x1440 桌面，2026-09-26 最近 300 张截图、299 个相邻对）实测：

| 指标 | 实测值 |
| --- | --- |
| 距离最小值 | **6** |
| p25 | 7 |
| 中位数 | 9 |
| p75 | 11 |
| 平均值 | 10.04 |
| 最大值 | 38 |
| 距离 ≤ 5 的帧数 | **0 / 299（0.0%）** |

距离直方图（距离:帧数）：

```text
6:38  7:53  8:51  9:42  10:33 11:27 12:14 13:6  14:5  15:2  16:5
17:3  18:1  19:4  20:2  21:3  22:1  26:2  31:1  32:2  35:1  37:1 38:2
```

**阈值 5 低于观测到的最小距离 6，所以这一帧永远不可能被判为相似 —— 跳过率实测为 0%。**
界面上的「已跳过重复」长期是 0，就是从这里来的。

### 为什么不是「把阈值调大」就完事

同一画面（滚动一屏文字、光标移动、时钟跳秒）的距离是 6~16，
真正换应用 / 换页面的距离是 17~38，中间**没有空隙**，直方图上 14~22 这一段两类是交错的。
阈值取在这个区间里，无论取多少都会同时犯两种错：要么继续漏掉大量重复，
要么把真实变化也当成重复丢掉。

根因在 dHash 本身：它每一位只回答「这两格谁更亮」，两格亮度接近时这一位就被噪声翻转。
截图分辨率越高，缩到 9x8 之后每格覆盖的像素越多，翻转就越容易。

## 3. 现在的做法：固定灰度网格 + 平均绝对差

指纹换成 **32x18 的灰度网格**（576 格）：

1. 把截图 `resize` 到 32x18；
2. 用标准亮度公式 `0.299R + 0.587G + 0.114B` 把每格转成 0~255 的灰度；
3. 两帧逐格求差的绝对值再取平均，得到**平均绝对差（MAD）**；
4. `MAD ≤ 8` 判为相似。

同一批真实截图的实测结果（新规则，最近 300 张）：

| 判定 | 帧数 | MAD 最小 | MAD 平均 | MAD 最大 |
| --- | --- | --- | --- | --- |
| 跳过（相似） | 282 | 0.97 | 3.78 | **5.77** |
| 保留（不同） | 17 | **21.66** | 64.10 | 188.41 |

两个区间 **5.77 ~ 21.66 之间完全是空的**，阈值 8 落在中间，离两侧都有 1.3 倍以上余量。
实测取 8 / 10 / 12 得到的判定结果完全一致，所以这个值不敏感。

## 4. 实测效果

最近 300 张真实截图（09:42 ~ 11:49，约 127 分钟）：

```text
保留 18 张 / 跳过 282 张，跳过率 94.0%
```

保留的 18 张正好是这段时间里真正发生的内容切换，也就是「值得分析」的那些。
修复前同样的 300 张，跳过 0 张。

## 5. 代码与接口

| 文件 | 导出 / 位置 | 说明 |
| --- | --- | --- |
| `src/main/frameSignature.js` | `SIGNATURE_WIDTH = 32`、`SIGNATURE_HEIGHT = 18`、`SIMILAR_FRAME_TOLERANCE = 8` | 尺寸与阈值常量 |
| `src/main/frameSignature.js` | `graySignature(bitmap, width, height)` | BGRA 位图 -> 灰度网格 |
| `src/main/frameSignature.js` | `meanAbsoluteDifference(a, b)` | 逐格平均绝对差 |
| `src/main/frameSignature.js` | `isSimilarSignature(a, b, tolerance)` | 判定；缺失或长度不同一律返回 `false` |
| `src/main/capture.js` | `frameSignature(image)` | 缩图 -> 取位图 -> 调 `graySignature` |
| `src/main/capture.js` | `isSimilarFrame` | 转发 `isSimilarSignature`，保持 Recorder 只依赖注入的 capture |

判定逻辑刻意放在独立模块里：`capture.js` 需要 `require('electron')`，单元测试跑不起来；
`frameSignature.js` 是纯函数，可以直接 `node --test`。

## 6. 已知局限

- **只和上一张已保存的比**：切换成 A -> B -> A 会各存一张。这是有意的 ——
  中间确实发生过不同的内容，A 回来看第二眼也值得记录。
- **基准是进程内变量**：重启后第一帧一定保存，不会误丢。
- **换显示器或分辨率**：指纹长度跟着变，判定返回「不相似」，会多存一张，之后恢复正常。
- **两块不同的纯色画面**（例如两个纯白窗口）MAD 可能很小而被判为相似。
  极端情况，可接受。
