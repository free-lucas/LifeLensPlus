# 迁移与版本

## 1. 版本号

- 当前版本：`SCHEMA_VERSION = 4`（`src/main/db/schema.js`）
- 版本存放在数据库的 `PRAGMA user_version` 里，开发时可以用
  `sqlite3 lifelens.db "PRAGMA user_version"` 或 `DatabaseSync` 直接查看
- 启动日志会打印：`[DB] Schema version: 4`

## 2. migration 规则

`src/main/db/migrations.js` 是一个极简 runner：

1. 读取 `PRAGMA user_version` 得到当前版本 `from`
2. 如果 `from > SCHEMA_VERSION`（用户装过更新版本的程序）→ 抛错，拒绝降级运行
3. 按顺序执行 `MIGRATIONS` 中 `version > from` 的每一项
4. **每一项都在一个事务里完成**：`BEGIN IMMEDIATE` → 所有 DDL → `PRAGMA user_version = N` → `COMMIT`
5. 任一步失败整体 `ROLLBACK`，下一次启动从同一版本重新开始，不会留下半套 schema

约定：**已经发布过的 migration 不再修改**。需要改结构时追加新的 `version`，
旧版本原样保留，靠 `user_version` 决定从哪一版开始跑。

```js
// schema.js
const MIGRATIONS = [
  { version: 1, statements: [ACTIVITIES_TABLE, AI_JOBS_TABLE, ...INDEXES] },
  { version: 2, statements: [TIME_BLOCKS_TABLE, ...TIME_BLOCK_INDEXES] },   // Phase 8
  { version: 3, statements: [DIARIES_TABLE, ...DIARY_INDEXES] },            // Phase 9
  { version: 4, statements: EMBEDDING_STATEMENTS },                         // Phase 10
];
```

### 版本历史

| 版本 | 内容 | 阶段 |
| --- | --- | --- |
| 1 | `activities` + `ai_jobs` 两张表与四条索引 | Phase 6 |
| 2 | `time_blocks` 表 + `idx_time_blocks_status`（纯新增，不动旧表） | Phase 8 |
| 3 | `diaries` 表 + `idx_diaries_status`（纯新增，不动旧表） | Phase 9 |
| 4 | 三张表各加 `embedding_status` / `embedding_model` / `embedding_version` 与一条索引 | Phase 10 |

第 2 版只做**加法**：没有 `ALTER TABLE`、没有改列、没有删数据，
所以老库升级后原有记录与任务队列原样保留。
实测：把一个 `user_version = 1` 的库用当前代码打开，版本变成 2、`time_blocks` 建好、
原有 `activities` 行数不变，缺口扫描能正确识别旧记录所在的区块。

第 3 版同样是纯加法。第 4 版是**加列迁移**：
`ALTER TABLE ... ADD COLUMN embedding_status TEXT NOT NULL DEFAULT 'PENDING'` 加上两个可空列与一条索引。
因为默认值是 `PENDING`，老库升级后存量记录会自动进入待嵌入队列。
实测由 `test/database.test.js` 的 Test 3 覆盖（v2 库升级到 v4：补上新表与新列、老数据保留、
存量区块的 `embedding_status = 'PENDING'`）。

## 3. Phase 6 没有数据迁移

这是明确的产品决策（Phase 6 文档第 18/19 节）：

| 项目 | 状态 |
| --- | --- |
| Legacy JSON migration（读取旧 `activities-*.json`） | NOT IMPLEMENTED |
| Legacy JSON import（把旧 JSON 转成 SQLite 行） | NOT IMPLEMENTED |
| Legacy JSON compatibility（兼容旧字段 / 回退读取） | NOT REQUIRED |
| Normal JSON persistence（新的 JSON 写入） | REMOVED |

- 旧的 `2026-09-11_21.json`、`ai-jobs.json` 会留在用户磁盘上，但代码不读取、不导入、不依赖。
- 没有 JSON → SQLite 的迁移脚本，也没有为了兼容旧数据而增加的复杂分支。
- 因此 Phase 6 上线后，界面与统计只反映 SQLite 里已有的数据。

## 4. 未来加字段的正确做法

```js
// schema.js
const SCHEMA_VERSION = 4;
const MIGRATIONS = [
  { version: 1, statements: [/* 原始 DDL，不要动 */] },
  { version: 5, statements: ['ALTER TABLE activities ADD COLUMN source TEXT'] },
];
```

只改 `SCHEMA_VERSION` 与追加项，不修改已发布的旧版本；老库启动时自动补跑缺的那几版。
