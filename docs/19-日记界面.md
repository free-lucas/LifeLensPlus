# 日记界面（Phase 9）

## 1. 页面结构

「日记」是第三个标签页（`记录` / `动态` / `日记` / `看板`），整体包在 `#view-diary` 里：

```text
#view-diary
├── panel 6  日记日历
│   ├── #diary-calendar   月历（周一起始）+ 每天的状态点
│   └── #diary-status     「正在生成 N 天的日记 · 正在检查有没有漏掉的日记」
└── panel 7  这一天的日记
    └── #diary-detail     日期 + 概况 + 六段正文（或各种空态）
```

标签页切换沿用 Phase 8 的 `selectTab()`：切到日记 / 看板时各自 `reload()` 一次。
两条链路都是 Renderer → Preload → IPC → Main → SQLite，渲染层不碰数据库。

## 2. 日历

- **周一起始**，按「本月第一天是周几」补位，补满整周（2026 年 9 月是 5 行 × 7 列 = 35 格）；
- 补位的日期是 `<span>`（不可点），本月日期是 `<button data-day="YYYY-MM-DD">`；
- 未来日期 `disabled`；今天 / 选中日各有自己的样式类；
- 状态点 `renderDot(mark)` 用颜色区分：`PENDING`（生成中）、`FAILED`（失败）、
  `COMPLETED`（按这一天的**主要分类**着色）、有区块无日记（灰）、没有记录（空）；
- 每格 `title` 是一句可读的说明，例如
  `2026年9月15日 周二 · 6 个时间段 · 主要在学习 · 正在生成日记`；
- 点日期 → 重新拉这一天的详情；点 `‹` `›` 翻月时**保持同一个日号**
  （9 月 15 日 → 8 月 15 日；目标月没有这一天就退到月末，例如 1 月 31 日 → 2 月 28 日）；
- 停在当前月份时「下个月」按钮 `disabled`，不允许翻到完全属于未来的月份；
- 「回到今天」把选中日与日历都拉回当月今天。

## 3. 一天详情

标题行固定为：`<日期>` + 概况一行 + （有日记时）`重新生成` 按钮。概况行由 `metaLine()` 拼：

```text
7 个时间段 · 共 1 小时 10 分 · 7 张截图 · 主要在工作（4 段）
```

六段正文（`renderDiaryBody`）顺序固定：**简短总结 / 主要事项 / 高光 / 待办 / 优化建议 / 温馨提示**，
空数组给文案兜底（「这一天没有记录到明显的高光」「没有发现被落下的待办」…），
所有文本都过 `escapeHtml()`。

按数据状态分级显示，避免「空白页」：

| 状态 | 显示 |
| --- | --- |
| 这一天还没到 | 这一天还没到。 |
| 没有任何记录与截图 | 这一天没有记录。 |
| 有截图但还没汇总成区块 | 这一天的 N 条记录还没有汇总成时间段，日记会在汇总完成后自动生成。 |
| 有区块、还有区块在汇总 | 还有 N 个时间段在汇总，汇总完成后会自动生成这一天的日记。 |
| 有区块、日记还没生成 | 这一天的日记还没有生成，应用启动时会自动补上。 |
| `diary.status = PENDING` | 正在生成这一天的日记… |
| `diary.status = FAILED` | 日记生成失败：<错误> · <错误码>，可以点「重新生成」再试一次。 |
| 有失败区块 | 额外一行：这一天有 N 个时间段汇总失败，日记里可能缺了这部分。 |

### 3.1 默认打开前一天

需求 1.1：**默认打开前一天的日记**。`createDiaryView` 的 `selectedDay` 初值是
`shiftDayKey(dayKeyOf(new Date()), -1)`，日历游标跟它走，第一次 `reload()` 就拉这一天。

### 3.2 「重新生成」

`diaries` 行存在时详情里才有 `重新生成` 按钮（`data-day` 带上日期）。点击后：
按钮先置灰 → `regenerateDiary(day)` → 无论成功失败都重新 `reload()` 一次，
让界面回到真实状态（`PENDING` 会显示「正在生成这一天的日记…」）。

## 4. 生成状态提示

`renderDiaryStatus(snapshot)` 把主进程的快照拼成一行：

```text
正在生成 3 天的日记 · 正在检查有没有漏掉的日记 · 1 天生成失败
```

没有待生成 / 失败 / 扫描中的时候返回 `null`，元素 `hidden`（不占位）。
数据来自 `lifelens:diary-status`（`DiaryGenerator.snapshot()` + `countByStatus()`）。

## 5. 数据流

```text
renderer/diary.js
  ├── getDiary(day)                     -> lifelens:diary            -> diaries.getByDay + timeBlocks.daySummary + activities.countBetween
  ├── getDiaryDays({ from, to })        -> lifelens:diary-days       -> diaries.listDayMarks（整月一次查询）
  ├── getDiaryStatus()                  -> lifelens:diary-status     -> DiaryGenerator.snapshot
  └── regenerateDiary(day)              -> lifelens:diary-regenerate -> DiaryGenerator.regenerate（force 重建任务）
```

`reload()` 并发拉这三个接口；主进程广播 `{ type: 'diary' }`（生成完成 / 失败）时页面会再刷一次，
区块汇总完成广播 `{ type: 'summary' }` 时也会顺带刷新日记页。

## 6. 模块划分

`src/renderer/diary.js` 与 `timeline.js` / `dynamics.js` / `kanban.js` 同一套约定：

- 整个文件包在 IIFE 里（四个脚本都是 classic script，共享同一个全局作用域，
  同名的函数声明会互相覆盖——`pad` / `escapeHtml` / `formatMinutes` / `categoryClass` 都是重名函数）；
- 上半部分是纯函数，`module.exports` 暴露给 `node --test` 直接 require；
- 只有 `init()` 依赖 `window.lifelens` 与 DOM。

日期数学在 `main/day.js` 与 `renderer/diary.js` 各有一份：重复的只是稳定的日历计算，
换来两个层互不依赖（渲染层不做 IPC 之外的判断）。

## 7. 本阶段发现并修复的问题

- **标签栏漏了「看板」按钮**：`TAB_VIEWS` 与 `selectTab()` 都支持 `kanban`，`#view-kanban` 也写好了，
  但 `<nav class="tabs">` 里只有三个按钮，看板页在真实界面上根本点不到。
  纯函数单测发现不了（它们只测 `createKanbanView`），是真实 Electron 冒烟里数标签页时发现的。
- **日历的「未来」判断用字符串比较**：`day > today` 对 `YYYY-MM-DD` 是安全的（等长、字典序即时间序），
  这一点在《18-日记生成》的时间口径里已经约定，渲染层因此不需要构造 Date 再比大小。
