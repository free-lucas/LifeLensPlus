# 动态页界面（Phase 8）

代码：`src/renderer/dynamics.js`（渲染）+ `src/main/summaryIpc.js`（IPC）+
`src/renderer/index.html` / `src/renderer/styles.css` 里的 `.tabs` / `.view` / `.heatmap*` / `.dynamics-*`。

## 1. 页面结构

界面从「一页到底」改成两个标签页，共用同一个 `index.html`，靠 `hidden` 切换：

```text
header
├── #summary-state    「汇总中」标记（有排队或正在扫描时才显示）
└── #state            记录状态（原有）
nav.tabs
├── .tab[data-tab=overview]  记录   <- 原有内容，整体包进 #view-overview.view
└── .tab[data-tab=dynamics]  动态   -> #view-dynamics.view[hidden]

#view-dynamics
├── section.panel            #heatmap（含 .heatmap-legend）+ #heatmap-detail
└── section.records
    ├── #dynamics-filters    项目 / 软件 / 时间范围 / 自定义起止 / 清除筛选
    ├── #dynamics-timeline   .dynamics-list（卡片）
    ├── #dynamics-status     加载中 / 继续下滑 / 没有更多了 / 错误
    └── #dynamics-sentinel   IntersectionObserver 的哨兵
```

`renderer.js` 里的 `selectTab(name)` 负责切 `.tab.active` 与 `.view[hidden]`；
切回动态页时重新 `reload()`（热力图画的是「最近 12 小时」，按当前时间重新对齐一次）。

## 2. 热力图

「最近 12 小时」的网格：**列 = 小时（12 列），行 = 一小时里的 6 个 10 分钟槽**，共 72 个点。
CSS 用 `grid-auto-flow: column`，所以 JS 生成的槽位也是**按列优先**（先填满一个小时的 6 行，再进下一列）。

| 函数 | 作用 |
| --- | --- |
| `heatmapSlots(now, { columns, rows })` | 生成 72 个槽位（`start` / `startMs` / `column` / `row` / `future`） |
| `heatmapRange(now, { columns })` | 一次查询的时间范围：`[第一列整点, 最后一列结束)` |
| `renderHeatmap(slots, blocks, selectedMs)` | 拼出「行标 + 网格 + 小时标」三段 HTML |

每个点是一个 `<button class="heat-cell">`，配色由区块分类决定：

| 类名 | 含义 |
| --- | --- |
| `cat-fun` / `cat-work` / `cat-study` / `cat-social` | 娱乐 / 工作 / 学习 / 社交 |
| `cat-pending` | 有记录但还没汇总（含 `FAILED`） |
| `future` | 还没到的时间（`disabled`，不可点） |
| 无额外类名 | 这个 10 分钟没有记录 |
| `selected` | 当前选中的点 |

`title` 给出可读提示：`10:00–10:10 工作 写《2026 年中报告》` / `10:30–10:40 还没到` /
`09:50–10:00 没有记录` / `… 汇总中` / `… 汇总失败`。

点一个点后 `#heatmap-detail` 展开该区块的详情（项目、分类、描述、软件 tag、待办、
截图条数）；没有记录的点显示「这个时间段没有记录」。区块数据来自
`listBlocksBetween()` 的一次范围查询，只查 72 个槽位覆盖的这 12 小时。

## 3. 动态时间线

每张卡片是一个 10 分钟区块：

```text
10:00–10:10  [工作]  2026-09-15
写《2026 年中报告》                                     <- .dynamics-project
整理上半年数据，并把结论补进报告里。……                  <- .dynamics-description
[Word] [Chrome]                                        <- .dynamics-tag
可能遗漏的待办：补充上半年的数据                          <- .dynamics-todos（可空）
```

- 未汇总的区块只显示「汇总中…」，失败显示「汇总失败：原因」，都不铺内容。
- 分页 `PAGE_SIZE = 20`，`offset` 语义，与 Timeline 一致。
- **纵向滑动加载**：列表底部的 `#dynamics-sentinel` 进入视口（`rootMargin: 240px`）就取下一页；
  没有 `IntersectionObserver` 时退化成手动「加载更多」按钮的语义（哨兵不会触发）。
- `#dynamics-status` 提示「加载中… / 继续向下滑动加载更多 / 没有更多了 / 加载更多失败：…」。
- 空态分两种：有筛选条件时是「没有符合条件的动态」，没有筛选时是「还没有动态记录」。

## 4. 筛选

| 控件 | 取值 | 说明 |
| --- | --- | --- |
| `#dynamics-project` | 项目名 | 选项来自 `listFacets().projects`（`DISTINCT project`） |
| `#dynamics-software` | 软件名 | 选项来自 `listFacets().software`（`json_each` 展开去重） |
| `#dynamics-range` | `all` / `today` / `yesterday` / `last7` / `custom` | 闭开区间 `[from, to)` |
| `#dynamics-from` `#dynamics-to` | `YYYY-MM-DD` | 只在「自定义时间」时显示；结束日期含当天 |
| `#dynamics-clear` | — | 清空全部条件并重新查询 |

- `buildBlocksQuery(filters, { limit, offset, now })` 把界面状态翻译成数据层参数，
  空值不传（等价于不筛这一项）。
- 日期按**本地时间**解析（直接 `new Date('2026-09-15')` 会按 UTC 差一天）。
- 每次条件变化重新查第一页；`applyFacets()` 重建下拉选项并保留当前选择。
- 筛选在 Main / SQLite 层完成，界面不整批加载历史数据。

## 5. 「汇总中」标记

`TimeBlockSummarizer.snapshot()` → IPC `lifelens:summary-status` → `renderer.js` 的 `renderSummary()`：

- `scanning === true` 或 `stats.pending > 0` 时显示；文案 `汇总中 N`（N = 待汇总区块数）。
- `title` 附上失败数量（`还有 N 个时间段等待汇总，M 个汇总失败`）。
- 收到 `{ type: 'summary' }` 广播时更新标记，并让动态页 `reload()` 一次
  （某个区块刚好汇总完成后，卡片从「汇总中…」变成完整内容）。

## 6. 数据流

```text
Renderer（dynamics.js）
  └─ window.lifelens.getTimeBlocks / getTimeBlockFacets / getSummaryStatus
       └─ preload.js（contextBridge 白名单）
            └─ summaryIpc.js：lifelens:time-blocks / -facets / lifelens:summary-status
                 └─ TimeBlockRepository / TimeBlockSummarizer 快照
                      └─ SQLite time_blocks
```

与 Timeline 相同的约定：Renderer 只走 IPC，不碰 SQL；IPCs 单独成模块，测试注入假的 `ipcMain` 就能测契约。

## 7. 模块划分

`dynamics.js` 整个包在 IIFE 里（与 `timeline.js` 一样是 classic script，共享同一个全局作用域）：

- 上半部分是纯函数，通过 `module.exports` 暴露给 `node --test` 直接 `require`；
- 末尾的 `init()` 只在渲染进程里执行，创建 `window.lifelensDynamics`，**不自动 reload**
  （首屏由 `renderer.js` 的 `refreshAll()` 触发）。

导出清单：`PAGE_SIZE` / `HEATMAP_COLUMNS` / `HEATMAP_ROWS` / `HEATMAP_MAX_LIMIT` / `CATEGORY_CLASSES` /
`blockStartOf` / `startMsOf` / `blockRangeLabel` / `blockDayLabel` / `categoryClass` / `heatmapSlots` /
`heatmapRange` / `heatRows` / `buildBlocksQuery` / `hasActiveFilters` / `resolveTimeRange` /
`parseDateInput` / `renderHeatmap` / `renderBlockCard` / `renderBlockDetail` / `createFilterBar` /
`createDynamicsView`。

`blockStartOf` / `escapeHtml` / `pad` 这些名字与 `timeline.js` 重名——两个文件共享全局作用域，
但都只在各自的 IIFE 里使用，所以不会互相覆盖（有专门的用例守住这一点）。

## 8. 本阶段发现并修复的问题

- **`createDynamicsView` 里的内部函数遮蔽了模块级纯函数**：内部画热力图的函数直接叫
  `renderHeatmap()`，调用 `renderHeatmap(slots, blocks, selectedMs)` 时按作用域链解析到自己，
  变成无限递归（`RangeError: Maximum call stack size exceeded`）。首屏一渲染动态页就整块白掉，
  而所有纯函数单测都是绿的——因为没有任何用例真的跑过装配。
  修复：内部函数改名 `paintHeatmap()`。
  顺带补了 `test/dynamicsView.test.js` 的动态 13 / 14 两例：把 DOM 桩到刚好够用，
  真的调用 `createDynamicsView().reload()` 并断言画出来的 HTML。
  这两例在把名字改回 `renderHeatmap()` 后会立刻失败。
- 这是**真实 Electron 冒烟**发现的，不是单元测试发现的。教训：渲染层的纯函数测试要配一个
  「装配层至少能跑通一次」的用例。
- **`.view { display: block; }` 盖掉了 `hidden`**：作者样式表里的 `display` 优先于 UA 样式表的
  `[hidden] { display: none }`，所以标签页切换只改了属性、两个页面却一直同时显示。
  验证方式不能只看 `element.hidden`（它一直是 `true`），要看
  `getComputedStyle(el).display` —— 实测是 `block` 且 `getBoundingClientRect().height > 0`。
  修复：删掉这条规则（`.view` 是普通 `div`，本来就是 `block`），让 `hidden` 恢复生效。
  这与 Phase 7.3 的 `.timeline-custom-range` 是同一类坑。
